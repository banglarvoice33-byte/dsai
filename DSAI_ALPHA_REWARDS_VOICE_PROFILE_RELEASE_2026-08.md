# DSAI Alpha Rewards, Voice Onboarding, and Profile Release

## Implemented scope

The authenticated alpha dashboard now uses append-only contribution events generated by real Work Packet actions: packet creation, source/evidence attachment, review submission and approval. The server derives points from these events and exposes a user-scoped dashboard plus an aggregate leaderboard that never reveals email addresses. The leaderboard polls every 15 seconds and labels that freshness interval in Bengali. Referral events and reward records have separate persistence tables and are shown only when verified records exist; no commission, payout, or community membership is fabricated.

The onboarding guide now supports optional browser speech recognition. Microphone permission is requested only after the user presses the voice button. The guide shows listening and fallback states, supports Bengali locale input, keeps the transcript visible for user review, and sends the reviewed question to the existing protected dynamic guide procedure. Unsupported browsers and denied permissions fall back to typed input. Audio is not persisted by this feature.

The new `/profile` route provides user-owned display name, short bio, preferred language and `system | light | dark` theme preferences. The shared ThemeContext now exposes explicit selection in addition to the existing toggle. The Night Workdesk palette is responsive, contrast-aware and compatible with reduced-motion behavior. Workspace includes a direct Profile settings link.

The reusable `/home/ubuntu/skills/dsai-launch-workdesk/SKILL.md` package was updated with the verified event, reward, voice, profile and theme patterns, and passes `quick_validate.py`.

## Validation

The release passed 52 Vitest tests across 17 files, TypeScript no-emit, production build, deployment shell/Node syntax checks, skill validation, database migration review/application, and mobile screenshots for `/platform`, `/alpha` and `/profile` at 390×844. The existing Vite shared-entry chunk warning remains advisory and non-blocking.

## Remaining operator gates

A live referral program still requires an operator-controlled attribution source, fraud review, refund/reversal handling, terms, disclosure, payout provider and applicable tax/KYC/KYB decisions. Reward records are intentionally empty until those controls are configured. Browser speech recognition support varies by browser and may require HTTPS and user permission. Live LLM availability, OAuth, database credentials, malware scanning, storage deletion, backups and incident response remain deployment-owned gates.
